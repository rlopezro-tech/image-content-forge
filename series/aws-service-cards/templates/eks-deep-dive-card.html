Amazon EKS

Deep Dive

Key Takeaways

  • EKS manages the Kubernetes control plane.
  • Workloads still need a compute option.
  • Manifests define pods, services, and desired state.
  • IAM and Kubernetes RBAC both matter.
  • Add-ons connect workloads to AWS services.

When To Use It

Teams standardizing on Kubernetes APIs.
Portable workloads using ecosystem tools.
Microservices needing Kubernetes rollouts.
AWS-native identity, network, and storage.

Watch Out

EKS is Kubernetes, not ECS orchestration.
Compute lifecycle depends on node model.
Add-ons, ingress, storage, and autoscaling need ownership.
